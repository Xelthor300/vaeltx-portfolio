# 0. EXECUTIVE DOCTRINE

## 0.1 The job of the portfolio

VAELTX does not yet have the historical social proof of a mature agency. The website must therefore replace **borrowed credibility** with **observable competence**.

The portfolio must make a first-time visitor answer these questions, in this order:

1. **What does VAELTX actually do?**  
   Web strategy, UX/UI, development-ready systems and conversion-focused websites.

2. **Is the visual level materially better than a generic freelancer or template?**  
   The answer must be visible before the user reads a long paragraph.

3. **Can this studio think, not only decorate?**  
   Architecture, interaction logic, responsive behavior, accessibility and implementation notes must prove it.

4. **Are the projects real client engagements?**  
   No. They are independent concept projects, and the site says so without apology or visual shame.

5. **Does VAELTX understand different commercial contexts?**  
   The four projects must demonstrate local services, creative work, premium B2B and ecommerce as genuinely different product systems.

6. **What happens if I contact them?**  
   The contact flow, process and ownership language must reduce uncertainty.

7. **Is there a clear next action?**  
   Work → understand fit → start a project.

The site is successful when the absence of old client logos stops being the dominant question because the visitor has already seen enough quality, care and transparency to continue.

## 0.2 Commercial target and decision psychology

Primary prospect: a buyer considering roughly **USD $1,000–$5,000** for a first website, redesign, landing page, implementation or focused ecommerce work.

This buyer rarely purchases “art direction” in isolation. They purchase a reduction in four risks:

- **Perception risk:** “Will my business look amateur?”
- **Clarity risk:** “Will people understand what we do?”
- **Execution risk:** “Will the site break, drag, or look bad on mobile?”
- **Collaboration risk:** “Will the project become vague, slow or impossible to manage?”

VAELTX should therefore sell through **visible systems**:
- clear information architecture;
- disciplined responsive design;
- conversion pathways;
- explicit project stages;
- measurable technical quality where it is actually measured;
- precise components and states;
- a professional inquiry experience.

## 0.3 Positioning sentence

**Visible headline direction:**  
> Websites with structure, character and a clear next action.

**Supporting positioning:**  
> VAELTX is an independent web & conversion studio designing high-clarity digital experiences for businesses that need to look credible, explain value quickly and turn attention into action.

This deliberately avoids unsupported promises such as “we grow revenue” or “we increase conversions by X%.” VAELTX controls design quality, interaction clarity, implementation discipline and the path to action; business outcomes depend on variables outside the interface.

## 0.4 The experiential idea: PRECISION THEATRE

The parent site is built around one creative principle:

**PRECISION THEATRE = editorial clarity × cinematic project presentation × evidence-based technical proof.**

The site changes mode depending on what the visitor is doing:

### MODE A — CANVAS
Used for:
- positioning;
- services;
- process;
- about;
- reading;
- forms;
- decisions.

Feel:
- warm off-white or neutral light ground;
- sharp typography;
- visible grid logic;
- minimal visual noise;
- content-first.

Purpose:
- make the studio understandable and credible.

### MODE B — STAGE
Used for:
- selected work;
- project introductions;
- immersive media;
- next-project transitions;
- portfolio chapters.

Feel:
- deep graphite;
- oversized media;
- project color entering the frame;
- cinematic pacing;
- constrained motion.

Purpose:
- make craft impossible to miss.

### MODE C — LAB
Used for:
- responsive proof;
- interaction specimens;
- component states;
- accessibility/performance evidence;
- implementation notes.

Feel:
- technical but human;
- structured tables, rulers, viewport labels, state comparisons;
- no fake “terminal” aesthetic.

Purpose:
- show that the visual work survives real constraints.

**The important distinction:** Canvas, Stage and Lab are not three themes. They are three narrative functions in one system.

## 0.5 Non-negotiable principles

### P1 — Proof before adjectives
If the interface can demonstrate it, do not claim it first.

### P2 — One dominant intention per viewport
Every screen has one primary reading target and one primary action. Secondary elements support, not compete.

### P3 — Motion must explain topology, hierarchy or state
No animation exists merely because it looks expensive.

### P4 — Project worlds are sovereign
Each concept has its own typography, grid rhythm, image grammar, navigation behavior, interaction density and motion signature.

### P5 — Never manufacture maturity
No invented awards, brands, metrics, testimonials, team size, years, traffic, revenue or conversion lift.

### P6 — Technical evidence is dated evidence
Any performance/accessibility score shown publicly includes method, date and environment.

### P7 — Mobile is a different composition, not a compressed desktop
Content order, controls, cropping, sticky behaviors and density are deliberately re-authored.

### P8 — Restraint is a premium signal
Luxury is not “more effects.” It is confidence in hierarchy, spacing, language and timing.

### P9 — The contact page is part of the portfolio
A premium website that ends in a generic form loses credibility at the exact moment of conversion.

### P10 — Every decorative decision must survive the deletion test
If removing an element improves clarity without reducing identity, remove it.

## 0.6 What VAELTX must never look like

- generic SaaS landing page;
- Web3 / crypto / neon dashboard;
- “creative agency” with meaningless 3D blobs;
- award-site scroll experiment that makes basic navigation difficult;
- black site + orange accent copied across every page;
- portfolio made only of mockups with no reasoning;
- fake enterprise agency;
- page full of rounded cards;
- terminal cosplay;
- heavy parallax;
- auto-playing background film competing with copy;
- text that constantly splits, rotates or scrambles;
- fake metrics used as visual decoration;
- concept projects disguised as clients.

## 1.1 Trust equation

VAELTX should build trust from six visible layers:

| Layer | What the visitor sees | Where it appears |
|---|---|---|
| Craft | High-quality art direction and composition | Hero, Work, case studies |
| Reasoning | UX decisions with rationale | Case studies, Process |

| Transparency | Concept disclosure, scope, ownership | Project headers, About, Contact |
| Predictability | Clear process and deliverables | Process, Services, inquiry flow |
| Care | Responsive, keyboard, focus, empty/error states | Every interactive surface |

The portfolio should never try to compensate for missing testimonials by shouting harder. It should increase the amount of evidence the visitor can inspect.

## 1.2 Conversion architecture

Three action levels:

**Level 1 — Proof**
- View selected work
- Open case study
- Explore interaction specimen

**Level 2 — Fit**
- See services
- Read process
- Review standards

**Level 3 — Contact**
- Start a project
- Send project brief
- Use verified email / WhatsApp only if owner confirms

Do not place three equally loud CTAs in one cluster. A viewport gets one dominant action.

## 1.3 Evidence hierarchy

Use in this order:
1. work visible on screen;
2. documented decisions;
3. responsive comparison;
4. component and state quality;
5. measured technical checks;
6. process transparency;
7. only later, real third-party social proof when it exists.

## 1.4 Concept-project disclosure system

Public label:
**Independent Concept Project**

Short explanation:
**“Self-directed concept created by VAELTX to demonstrate strategy, UX, interface design and implementation intent. Not commissioned client work.”**

Placement:
- Work card: compact status line.
- Case-study header: visible metadata.
- Inside concept site: slim “Concept by VAELTX” utility bar or footer note.
- About: one explicit disclosure paragraph.
- Never only in legal fine print.

Styling:
- neutral metadata;
- not a red warning;
- not a trophy badge;
- no language implying a real commercial engagement.

# 2. GLOBAL CREATIVE DIRECTION — CANVAS / STAGE / LAB

## 2.1 Visual temperament

Desired perception:
- exact;
- calm;
- premium;
- technically literate;
- editorial;
- intentional;
- independent;
- commercially aware;
- contemporary without fashion-chasing.

The site should feel closer to a carefully edited architecture monograph plus a product-quality interface than to an “agency template.”

## 2.2 Reference mixture

| Influence | Contribution | Avoid |
|---|---|---|
| Swiss / International Style | grid, alignment, typographic hierarchy | sterile museum coldness |
| Editorial design | pacing, captions, asymmetric media, section numbering | arbitrary magazine chaos |
| Industrial documentation | labels, diagrams, measurements, state matrices | terminal/hacker cosplay |
| Contemporary luxury | restraint, material-like surfaces, silence between objects | ornamental serif overload |
| Cinematic language | staging, reveal, sequencing | video-for-video’s-sake |
| Modern product design | states, responsive logic, accessible interactions | SaaS card factories |
| Restrained brutalism | hard edges, exposed structure, decisive scale changes | hostility, illegibility |

Recommended weighting:
**40% editorial/Swiss · 25% product-system rigor · 20% cinematic staging · 10% luxury restraint · 5% restrained brutalism.**

## 2.3 Composition laws

1. Master alignment must be visible.
2. Large type may break scale, not grid logic.
3. One section can break the container only when that break is the idea.
4. Rules/dividers are structural, never decorative confetti.
5. Large media gets breathing room; small media must be informational.
6. Captions align to the media edge they describe.
7. Project color is allowed to invade the parent brand only inside Stage transitions.
8. Never center long body copy.
9. Center alignment is reserved for short emotional pauses, not information-heavy sections.
10. Every full-bleed moment must have a quieter section before or after it.

## 2.4 The signature visual move: The Aperture

VAELTX’s recognizable motion/composition device is **The Aperture**.

At rest:
- project preview appears as a precisely cropped rectangle occupying 5 columns.
- a 1px frame indicates its boundary.
- metadata sits outside the image, not over it.

On intentional reveal:
- the media aperture expands laterally and vertically into Stage mode;
- surrounding canvas darkens rather than simply fading away;
- project color enters as a controlled edge or field;
- title and metadata re-anchor to the new composition;
- no zoom greater than 1.035 on photographic media.

Meaning:
- “You are moving from reading about the studio into inspecting the work.”

Reduced motion:
- direct color/background change + instant layout state with 120ms opacity crossfade.

## 2.5 The signature technical move: Viewport Relay

A responsive demonstration is shown as one continuous component that changes viewport state:
- desktop frame;
- tablet frame;
- mobile frame;
- the same content remains logically connected;
- labels explain what changes in hierarchy, not just dimensions.

The transition is not a flashy device mockup carousel. It is a proof specimen.

Default: no shadows.

Depth should usually come from:
- background shift;
- border;
- scale of media;
- negative space;
- occlusion in project imagery.

## 3.7 Borders

- `1px line-0`: baseline.
- `1px line-1`: strong.
- `2px focus`: keyboard only.

## 3.9 Form system

Field anatomy:
`Label → optional helper → control → validation message`

Input:
- height 54;
- 16px text minimum;
- 16px horizontal padding;
- background surface-0;
- 1px border;
- radius 4;
- never rely on placeholder as label.

Textarea:
- min 144;
- resize vertical on desktop;
- no fixed-height clipped content.

Select:
- native semantics retained;
- visual shell permitted;
- native select preferred on mobile.

Checkbox:
- 20–22px visual;
- 44px minimum interactive region;
- label toggles control.

Error:
- border + icon + plain-language text;
- `aria-invalid` and described-by relation;
- no “Invalid input” when a useful instruction is possible.

Loading:
- submit button width does not jump;
- form prevents duplicate submit;
- button label becomes “Sending…”;
- status announced.

Success:
- replace form with a real confirmation block;
- preserve submitted name if appropriate;
- never promise a response window unless confirmed.

## 3.10 Iconography

Style:
- 1.5px–1.75px stroke;
- geometric but not sterile;
- round line caps only where appropriate;
- no mixed icon families.

Use:
- arrow northeast = external/live;
- arrow right = continue;
- chevron = disclosure/navigation hierarchy;
- plus/minus = accordion;
- check = confirmed state;
- no decorative icon beside every heading.

# 4. INTERACTION & MOTION OPERATING SYSTEM

## 4.1 Motion philosophy: KINETIC CLARITY

Motion communicates:
1. where an element came from;
2. where it is going;
3. what changed;
4. what deserves attention;
5. what belongs together.

Motion never exists to continuously entertain.

## 4.2 Timing tokens

| Token | Duration | Use |
|---|---:|---|
| `snap` | 90ms | pressed state |
| `fast` | 160ms | hover, underline, icon |
| `base` | 280ms | panels, accordion |
| `flow` | 420ms | media state, nav overlay |
| `reveal` | 620ms | major content reveal |
| `cinema` | 820ms max | aperture / page-stage transition |

Anything beyond 820ms requires explicit narrative justification.

## 4.3 Easing

- **Out / enter:** `cubic-bezier(0.16, 1, 0.3, 1)`
- **Standard:** `cubic-bezier(0.2, 0, 0, 1)`
- **In-out:** `cubic-bezier(0.65, 0, 0.35, 1)`
- **Pressed:** linear or short standard; no spring bounce.
- Spring physics only allowed for Vault cart quantity or card-stack affordance, with low overshoot.

## 4.4 Distance and scale laws

- text reveal vertical travel: 12–20px;
- section reveal: 20–28px max;
- hover image scale: 1.012–1.025;
- Stage aperture scale: never fake depth with >1.035 image zoom;
- icon travel: 2–4px;
- no 100px content fly-ins;
- no 3D rotation on parent brand.

## 4.5 Stagger law

- max 4–5 items staggered;
- gap 45–70ms;
- list longer than 5 items: reveal as group, not waterfall;
- keyboard navigation must never wait for animation.

## 4.6 Motion patterns

### M01 — Page Resolve
Trigger: route arrival.  
Sequence:
1. canvas appears immediately;
2. navigation settles at 0ms;
3. eyebrow and title reveal by clip/mask, 420–560ms;
4. supporting text follows 70ms later;
5. first actionable CTA is interactive immediately, even if visual reveal is finishing.

Never hide content behind a preloader.

### M02 — Aperture Transfer
Used when entering a case study from a Work preview.
- selected project media becomes the destination media anchor when feasible;
- background moves Canvas → Stage;
- title metadata repositions rather than disappears/reappears;
- 620–820ms;
- if shared-element transition is unavailable, use a disciplined crossfade + crop expansion, not a fake complex sequence.

### M03 — Evidence Rail
In Lab modules, desktop/tablet/mobile specimens switch with a segmented control or scrubber.
- no automatic carousel;
- selected viewport receives a clear active state;
- size transition 280–420ms;
- annotations update after the frame settles, 80ms delay.

### M04 — Section Index
A tiny vertical progress marker can indicate current case-study chapter on desktop >1180px.
- no scroll hijacking;
- marker moves continuously;
- chapter labels update discretely when their heading crosses ~35% viewport height.

### M05 — Intentional Image Reveal
- use clip from 0→100% only for the first image in a major chapter;
- following images use opacity + 12px;
- do not repeat a dramatic mask 20 times.

### M06 — Hover Lens
For Work previews:
- pointer position may shift crop focal point by max 1.5%;
- title arrow extends 4px;
- project status remains static;
- disabled on coarse pointer.

### M07 — Navigation Overlay
Mobile:
- overlay enters from top with 420ms ease-out;
- page underneath dims, does not scale;
- links reveal as a group;
- close reverses faster, 280ms;
- focus trapped;
- Escape closes where keyboard exists.

### M08 — Form State
- error message expands height, not overlay;
- 180–240ms;
- no shaking inputs;
- focus remains logical.

### M09 — Accordion
- content height + opacity, 280ms;
- icon rotates 90° or plus→minus;
- headings remain fully readable.
- reduced motion: instant open/close.

### M10 — Cross-project Transition
At case-study end:
- next project color begins as a 4–8px edge band;
- as user enters the next-project CTA region, color expands to 30–40% of field;
- click completes transition.
- This creates anticipation without autoplay.

## 4.7 Project-specific motion signatures

**Northstar:** mechanical, quick, grounded. Panels lock into place; no float.  
**Mira:** slow editorial reveal, soft crop drift, paper-like opacity.  
**Axiom:** measured data/diagram assembly; no fake chart-growth results.  
**Vault:** tactile commerce feedback, foil highlight on eligible card media only, controlled drawer physics.

## 4.8 Reduced motion

When `prefers-reduced-motion: reduce`:
- remove spatial transforms;
- no autoplay;
- no shared-element travel;
- no tilt/parallax;
- keep state visibility via color, border and short opacity ≤120ms;
- scroll-triggered content is already present; no content may depend on animation completion.

## 4.9 Motion performance budget

- only transform/opacity for continuous transitions where possible;
- max one large moving media object at a time;
- no permanent scroll-bound blur;
- no canvas/WebGL on VAELTX parent site;
- respect 60fps target on mid-range mobile;
- decorative motion is the first feature removed under constrained devices.

# 21. RESPONSIVE SPECIFICATION

## 21.1 Breakpoint philosophy

Breakpoints are design checkpoints, not device labels. Layout remains fluid between them.

## 21.2 1440

- 12 columns;
- 64 margins;
- 24 gutters;
- H1 80–88 typical;
- full desktop nav;
- large media and asymmetric layouts allowed;
- forms can use 5/7 or 6/6 split.

## 21.3 1280

- 12 columns;
- 48 margins;
- 20 gutters;
- reduce whitespace before typography;
- portfolio media still asymmetric;
- ecommerce grid 3–4 columns depending card min width.

## 21.4 1024

- 12 logical, 8 visual;
- 40 margins;
- 20 gutters;
- H1 60–68;
- nav may remain desktop if items fit with 44px targets; otherwise collapse at a documented threshold.
- sidebars narrow or convert to rails.

## 21.5 768

- 8 columns;
- 32 margins;
- 16 gutters;
- mobile/tablet nav;
- two-column editorial sections become 5/3 or full-width stack based on reading order;
- sticky sidebars usually become inline;
- diagrams may use full width.

## 21.6 430

- 4 columns;
- 20 margins;
- 12 gutters;
- H1 50;
- section padding 72;
- CTAs full width only where priority benefits;
- portfolio images primarily one column;
- forms one column;
- footer 2 logical groups.

## 21.7 390

- 20 margins;
- H1 46;
- hero media 4:3 / project-specific;
- sticky bars max 64 high;
- no horizontal text overflow.

## 21.8 360

- 18 margins;
- H1 42;
- tighten heading tracking carefully;
- controls remain 44+ high;
- do not reduce body below 16;
- two-action bars may become one primary + icon secondary if needed.

## 21.9 Responsive transition rules

When moving down:
1. preserve task;
2. preserve reading order;
3. preserve action visibility;
4. reduce simultaneous information;
5. change component pattern when necessary;
6. remove decoration before shrinking useful controls.

## 21.10 Media rules

- art-directed sources for key hero crops;
- define focal points;
- never rely on `cover` to make every image magically work;
- mobile may use a separate crop;
- logos/diagrams prefer vector where appropriate.

## 21.11 Forms

Desktop:
- related short fields may share row.
Mobile:
- one field per row;
- input types optimized;
- no two narrow text inputs side by side at 360.

## 21.12 Footer

Desktop:
- CTA field;
- 3–4 utility groups.
Mobile:
- CTA first;
- links in 2 columns or grouped rows;
- legal last;
- no accordion unless footer becomes unreasonably long.

The site first solves orientation, then proves craft, then reduces risk, then asks for contact.

# APPENDIX E — ROUTE-LEVEL EXECUTION CONTRACT

This appendix closes the gap between a visual blueprint and a buildable product specification. It does **not** replace the detailed project chapters above; it tells the implementation team what must be true on every route so no page becomes a generic afterthought.

## E.1 Universal 11-point page contract

Every public route must have an explicit answer for the following eleven questions before implementation is approved:

1. **Page goal** — what business/user outcome the page exists to create.
2. **User intent** — what the visitor is likely trying to resolve on arrival.
3. **Information hierarchy** — exact section order; not a list of interchangeable modules.
4. **Desktop composition** — grid occupancy, dominant alignment, media proportion and CTA position.
5. **Mobile recomposition** — authored order, hidden/condensed elements, sticky behavior, tap ergonomics and content cropping.
6. **Visible copy** — real provisional labels, headings and CTA language; no lorem ipsum in design review.
7. **Visual direction** — exact role of photography, screenshots, diagrams, product media or typographic space.
8. **Interaction states** — default, hover where relevant, focus, pressed, loading, error, success, empty and disabled where the component can reach them.
9. **Motion** — trigger, duration, easing, distance/scale, interruption behavior and reduced-motion equivalent.
10. **CRO** — primary action, secondary action, objection resolved and what must not compete with the primary action.
11. **Accessibility** — semantic heading structure, contrast, focus path, keyboard behavior, motion safety, labels and touch target rules.

A route fails design QA if any of these is left for the developer to invent.

# APPENDIX I — MOTION ACCEPTANCE TESTS

Motion is approved only when all statements below are true.

1. **Purpose named:** each animation has a stated purpose: orientation, hierarchy, feedback, continuity or brand expression.
2. **Input independence:** essential content/action does not require hover, fine pointer or motion support.
3. **Interruptible:** route/overlay animations can be interrupted by navigation or user input without leaving half-states.
4. **No scroll ownership:** the site never hijacks wheel/touch scroll to play a sequence.
5. **No delayed conversion:** primary actions are never held back to finish an entrance animation.
6. **Compositor-safe preference:** transform/opacity are preferred; layout animation is used only when component geometry genuinely changes.
7. **Reduced-motion parity:** `prefers-reduced-motion` removes spatial choreography while preserving state change and hierarchy.
8. **Viewport budget:** no more than one dominant continuous motion behavior per viewport; most viewports have none.
9. **Project sovereignty:** Northstar, Mira, Axiom and Vault do not inherit the same reveal choreography by default.
10. **Performance evidence:** any heavy canvas/WebGL/blur effect must prove its value and performance before shipping; the baseline design must work without it.

## I.1 Signature motion — implementation intent

### Aperture Transfer / VAELTX
Purpose: preserve spatial continuity from a portfolio preview into its case study. The selected project media expands toward the case-study stage while surrounding UI recedes. It is progressive enhancement; normal routing is the baseline.

- pointer activation: 620–820ms maximum total sequence;
- keyboard activation: same navigation result; visual transfer may be simplified;
- back navigation may restore origin position only if browser/history state is stable;
- never block route content longer than the visual transition;
- reduced motion: 120ms crossfade or immediate route paint.

### Viewport Relay / VAELTX
Purpose: prove responsive authorship. A controlled specimen switches the *same* page state between desktop, tablet and mobile frames while keeping the focal component anchored.

- activated by explicit tabs, not autoplay;
- frame resize 320ms, content crossfade 160ms after geometry settles;
- labels announce current viewport;
- mobile version uses a segmented control that never causes horizontal page overflow.

### Structural Trace / Northstar
Purpose: reinforce construction/inspection logic. A thin line traces between service/problem/process nodes only after content is visible.

- 260–380ms per segment;
- no continuous looping;
- removed entirely on reduced motion.

### Gallery Breath / Mira
Purpose: let artwork enter without turning the gallery into a UI demo. Crop mask opens 8–16px beyond final edge then settles subtly.

- 520–620ms;
- scale never exceeds 1.015;
- one-time reveal only;
- no parallax on small screens or reduced motion.

### Logic Build / Axiom
Purpose: explain sequence in a framework. Nodes appear in reading order and connectors resolve only after both endpoints are visible.

- node 160ms each, stagger 70–90ms;
- connector 260–320ms;
- no numeric growth animation;
- content is legible before the motion completes.

### Foil Response / Vault
Purpose: echo physical collector material on eligible foil product media, not decorate every card.

- pointer position maps to subtle highlight + ≤2.5° tilt;
- no effect on coarse pointer;
- stops instantly on pointer leave;
- no persistent GPU animation;
- the product image remains fully readable without it.
